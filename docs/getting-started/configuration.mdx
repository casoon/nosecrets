nosecrets loads `.nosecrets.toml` and `.nosecretsignore` from the repository root. Common generated
directories such as `.git`, `node_modules`, `target`, `dist`, `build` and coverage output are ignored
by default.

## Repository configuration

```toml
[ignore]
paths = ["vendor/", "fixtures/**"]

[allow]
patterns = ["^test_[A-Za-z0-9]+$"]
values = ["AKIAIOSFODNN7EXAMPLE"]

[entropy]
enabled = true
min_length = 20
threshold = 4.2
require_context = true
word_filter = true

[entropy.allow]
patterns = ["^[a-f0-9]{32,}$"]

[decode]
base64 = true

[scan]
max_file_size = 5242880
```

Global allow patterns and values apply to all findings. Entropy-specific patterns apply only to
the high-entropy detector. With `require_context = true`, entropy candidates must appear near terms
such as `secret`, `token`, `key`, `auth` or `password`. With `word_filter = true` (default),
candidates in which common English and programming words cover at least half of the characters, such as
`getUserAuthenticationTokenFromRequest` or `MAX_CONNECTION_RETRY_TIMEOUT`, are not reported.
Interpolation like `${VAR}`, access like `os.environ["X"]` and generic types like
`Promise<Foo<boolean>>` are skipped as well; a literal token next to them is still reported.

With `decode.base64 = true` (default), runs of 24 or more base64 characters (standard or URL-safe
alphabet) are decoded one level deep and the decoded text is matched against the rules, so a
base64-encoded token in a Kubernetes `Secret` is found. Set it to `false` to scan only the text as
written.

Files larger than `scan.max_file_size` bytes (default 5 MiB) are skipped; nosecrets states on stderr
how many. Set it to `0` to scan files of any size.

An unknown key anywhere in `.nosecrets.toml` stops the scan with an error that names the key.

## Fingerprint ignores

`.nosecretsignore` accepts one stable fingerprint per line. Add `:<path-glob>` to limit an exception:

```text
nsi_a1b2c3d4e5f6
nsi_b2c3d4e5f6a7:tests/fixtures/**
```

The CLI can append the same entries:

```sh
nosecrets ignore nsi_a1b2c3d4e5f6
nosecrets ignore nsi_b2c3d4e5f6a7 --path 'tests/fixtures/**'
```

## Inline ignores

Use an inline marker only when the reason is obvious beside the value:

```text
api_key = "documented-example" # @nosecrets-ignore
api_key = "documented-example" # @nsi test fixture
api_key = "documented-example" # gitleaks:allow
```

A marker must stand as a separate word, after whitespace or a comment opener. The same characters
inside an e-mail address or a longer word are not a marker.

<Callout type="caution">
  An allowlist suppresses a finding; it does not make the value safe. Prefer narrow path-scoped
  fingerprints for individual reviewed cases.
</Callout>
