## Scan modes

| Command | Source | Intended use |
| --- | --- | --- |
| `nosecrets scan --tracked` | Every tracked blob in the Git index | One-time baseline when adopting nosecrets |
| `nosecrets scan --staged` | Changed blobs staged for the next commit | Every pre-commit run |
| `nosecrets scan [PATHS]…` | Files and directories in the working tree | Ad-hoc scans |

`--tracked`, `--staged` and explicit paths are mutually exclusive. Both Git modes require a Git
repository. The tracked scan rejects an unmerged index instead of silently choosing one side.

## Scan options

| Option | Meaning |
| --- | --- |
| `--interactive` | Ask whether each finding should be added to `.nosecretsignore` |
| `--dry-run` | Print findings but always exit with status 0 |
| `--format text` | Human-readable terminal output; this is the default |
| `--format json` | Machine-readable JSON array |
| `--format sarif` | SARIF 2.1.0 log for GitHub code scanning |
| `--rules <FILE>` | Load an additional TOML rule file; repeat to load more than one |

Relative rule paths resolve from the repository root. Custom rules extend the built-in set.

## JSON output

`--format json` prints one array on standard output, empty when nothing was found:

```json
[
  {
    "path": "src/config.py",
    "line": 3,
    "column": 10,
    "rule_id": "github-pat",
    "rule_name": "GitHub Personal Access Token",
    "severity": "critical",
    "fingerprint": "nsi_1db61e13c133",
    "preview": "ghp_...wxyz"
  }
]
```

| Field | Type | Meaning |
| --- | --- | --- |
| `path` | string | Path relative to the repository root, with `/` as separator |
| `line` | integer | Line of the secret, starting at 1 |
| `column` | integer | Byte column of the secret within the line, starting at 1 |
| `rule_id` | string | ID of the rule; `high-entropy-string` for entropy findings |
| `rule_name` | string | Display name of the rule |
| `severity` | string | `critical`, `high`, `medium` or `low` |
| `fingerprint` | string | `nsi_…` value accepted by `.nosecretsignore` |
| `preview` | string | Masked secret; never the full value |

Fields may be added in a release. Renaming or removing one, or changing its type, is listed
under "Breaking" in the changelog. Notes such as skipped files go to standard error, so standard
output stays valid JSON.

## SARIF output

`--format sarif` prints a SARIF 2.1.0 log on standard output, so findings can be uploaded to GitHub
code scanning. Every finding becomes a result with the rule, the location and its `nsi_…`
fingerprint (`partialFingerprints`, key `nosecrets/v1`); the secret itself is never included.
`critical` and `high` map to the level `error`, `medium` to `warning`, `low` to `note`. Exit
codes are the same as for the other formats.

```yaml
- run: nosecrets scan --tracked --dry-run --format sarif > nosecrets.sarif
- uses: github/codeql-action/upload-sarif@v4
  with:
    sarif_file: nosecrets.sarif
```

`--dry-run` makes the scan exit with status 0 when it finds something, so the upload step runs and
code scanning shows the alerts; a scan that cannot run still exits with status 2 and fails the
job. To fail the job on findings as well, add a plain `nosecrets scan --tracked` step.

## Ignore command

```text
nosecrets ignore [--path <PATH>] [--file <FILE>] <FINGERPRINT>
```

Without `--file`, the command appends to `.nosecretsignore` in the repository root. `--path`
restricts the fingerprint to a path glob.

## Exit codes

- `0`: no critical, high or medium findings; low-severity findings may still be shown.
- `1`: at least one critical, high or medium finding.
- `2`: nosecrets could not complete the scan, for example because a path does not exist, a file or
  Git object could not be read, the configuration was invalid or `--staged` ran outside a Git
  repository. `--dry-run` does not change this status.

When several rules match the same text, the most severe one is reported; findings are listed in
order of path, line and column.
